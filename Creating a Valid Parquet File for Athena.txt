🟢 Creating a Valid Parquet File for Athena - Practical Notes
---------------------------------------------------------------
🎯 Objective:  
Create a valid Parquet file, upload it to Amazon S3, create an Athena external table, and successfully query the data.
During the practical session, a Parquet file was required to validate Athena's support for the Parquet file format.

As an Initial attempt, a text file was manually created and saved with a .parquet extension before being uploaded to Amazon S3. 
An Athena external table was then created on top of the uploaded file.The table creation completed successfully 
because Athena stores only metadata during table creation and does not immediately validate the file content.

📌 However, when the following query was executed:
SELECT * FROM employee_parquet_file;

📌 Athena returned the error:
HIVE_BAD_DATA: Malformed Parquet file
Expected magic number: PAR1


📌 This initiated a troubleshooting exercise to understand:
-------------------------------------------------------------

👉 What makes a file a valid Parquet file.
👉 Why Athena rejected the uploaded file.
👉 How to generate a genuine Parquet file correctly.
👉 How Athena validates Parquet file structure during query execution.

❌ Initial Attempt (Failed)
--------------------------------
Created a file named: employee.parquet
using Notepad++ and uploaded it to S3.

Created Athena table:
CREATE EXTERNAL TABLE employee_parquet_file (...)

Query executed: SELECT * FROM employee_parquet_file;

Athena returned: 
HIVE_BAD_DATA: Malformed Parquet file
Expected magic number: PAR1

Verification
File Name: employee.parquet
File Size: 95 bytes


📌 Root Cause :
-----------------
The file was created using a text editor and saved with a .parquet extension.
Although the file name ended with .parquet, the content was still plain text and not a genuine Parquet binary file.

📌 Observation :
-----------------
👉 Simply changing a file extension from .csv or .txt to .parquet does not create a valid Parquet file.
👉 Athena validates the actual Parquet binary structure and not just the file extension.

🧹 Cleanup Before Retest
--------------------------
🔸 Deleted the invalid file from S3: employee.parquet
🔸 Dropped the Athena table: DROP TABLE employee_parquet_file;
🔸 -This ensured the next test started with a clean environment.

🟢 Step 3: Create a Python Script
----------------------------------
Create a file named: create_parquet.py
The script creates employee data using a Pandas DataFrame and generates a Parquet file.

📌 Python Code:
----------------
import pandas as pd
import os
 
df = pd.DataFrame({ 
'id':[1,2,3,4,5],
'fname':['Sham 1','Sham 2','Sham 3','Sham 4','Sham 5'],
'lname':['G','G','G','G','G'],
'age':[30,30,26,26,26]
})
 
file_path = r'C:\Users\ShamG\Desktop\employee_new.parquet'
df.to_parquet(file_path, index=False)

print("employee.parquet created successfully")
print("File Size:", os.path.getsize(file_path), "bytes")

🔸 The script creates sample employee data in a Pandas DataFrame and converts it into a Parquet file.
🔸 Important: At this stage only the Python script is created.
🔸 The Parquet file does not exist yet.

➡ Points to Note:
--------------------
👉 PAR1 is the magic number (signature) that identifies a valid Parquet file.
👉 Athena looks for the PAR1 signature before reading the file.
👉 If PAR1 is missing, Athena treats the file as corrupted or not a Parquet file and throws:

HIVE_BAD_DATA: Malformed Parquet file
Expected magic number: PAR1

➡ The employee_new.parquet file generated using Python + Pandas + PyArrow contained a valid PAR1 signature,
