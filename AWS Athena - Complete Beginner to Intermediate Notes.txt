🟢 What is AWS Athena?

🔸 Serverless Query Service.
🔸 Pay only for the Data scanned.
🔸 It allows us to query data stored in Amazon S3 using SQL.
🔸 No Server Installation or Database Setup is required.
👉 Example : S3 Data → Athena Query → Results


🟢 Why do we use AWS Athena?

🔸 Analyze files/data stored in S3.
🔸 Generate reports using SQL.
🔸 Validate data uploaded by Data Engineering teams.
🔸 Explore CSV, JSON, and Parquet files.
🔸 Perform ad-hoc analysis on historical data.
👉 Supported File Formats ->  CSV, JSON, Parquet, ORC, and Avro


🟢 Athena Vs Redshift

📌 Athena:
🔸 Serverless Query engine.
🔸 Reads data directly from S3.
🔸 Best for ad-hoc and light-weight analysis.
🔸 No data loading required.

📌 Redshift:
🔸 Data warehouse.
🔸 Data is stored and queried within Redshift.
🔸 Best for historical reporting and large analytical workloads.

📌 Simple Rule:
🔸 Light-weight analysis → Athena
🔸 Enterprise reporting / Data warehouse → Redshift


🟢 Athena Vs QuickSight

📌 Athena:
🔸 Query tool
🔸 Provides tabular output
🔸 Runs SQL statements

📌 QuickSight:
🔸 Visualization tool
🔸 Generates charts and dashboards
🔸 Uses Athena as a data source

📌 Simple Rule:
🔸 Athena = Query Data
🔸 QuickSight = Visualize Data

📌 Output format - (Athena)
🔸 Table

📌 Output format (QuickSight / Power BI / Tableau)

🔸 Visual reports

👉 Graphical Output in Athena  -> It does not generate dashboards.

🟢 What is AWS Glue Data Catalog?

🔸 Glue Data Catalog is a metadata repository.
🔸 Stores databases, tables, columns, datatypes, partitions and S3 locations.
🔸 Does not store actual data.

Stores:
🔸 Databases
🔸 Tables
🔸 Columns
🔸 Datatypes
🔸 S3 Locations
🔸 Partitions

👉 Actual data stays in S3.


🟢 Athena and Glue Data Catalog

Athena:
🔸 Query engine
🔸 Executes SQL queries on data stored in S3.

Glue Data Catalog:
🔸 Metadata repository
🔸 Stores database definitions
🔸 Stores table definitions
🔸 Stores column information and data types

👉 Athena uses Glue Data Catalog metadata to understand the structure of data stored in S3.


🟢 Athena and Glue Catalog Validation

🔸 Create a table in Athena.
🔸 Open Glue Data Catalog.
🔸 Verify the table exists.
🔸 Create another table in Athena.
🔸 Verify it is automatically visible in Glue Catalog.

👉 Observation: Athena stores metadata in Glue Data Catalog.

🟢 What is Glue Crawler?

🔸 AWS Glue Crawler automatically scans data sources such as Amazon S3.
🔸 Detects the schema (columns and data types).
🔸 Creates metadata in Glue Data Catalog.
🔸 Creates tables automatically if they do not exist.
🔸 Updates existing table definitions when data structure changes.
🔸 Identifies new columns and partition information.

👉 Purpose:
Automatically discover and maintain metadata for data stored in S3.

🟢 Why do we need a Crawler?

📌 Day 1 : Source file has 3 columns -> id,name,salary

👉 Crawler scans the file and creates metadata with 3 columns in Glue Data Catalog.

📌 Day 2 : New columns are added -> department, location
Total Columns = 5

Problem:
👉 Glue Data Catalog metadata still contains only 3 columns.
👉 Athena cannot recognize the newly added columns.
👉 Metadata mismatch occurs between S3 data and Glue Catalog.

Solution:
👉 Run Glue Crawler.
👉 Crawler scans the latest files in S3.
👉 Detects the new columns.
👉 Updates Glue Catalog metadata from 3 columns to 5 columns.
👉 Athena can now query all 5 columns successfully.

📌 Simple Flow

S3 File Updated
        ↓
Metadata Out of Sync
        ↓
Run Glue Crawler
        ↓
Glue Catalog Updated
        ↓
Athena Reads Latest Schema

🟢 Schema Evolution Example

📌 Day 1

employees_v1.csv
emp_id
emp_name
department
salary
location
Total Columns = 5

📌 Day 2

employees_v2.csv

New Columns Added:
email
joining_date
manager
Total Columns = 8

Problem:
👉 Glue Catalog metadata still shows only 5 columns.
👉 Athena cannot access the newly added columns.

Solution:
👉 Run Glue Crawler.
👉 Crawler scans the updated file in S3.
👉 Glue Catalog metadata is updated from 5 columns to 8 columns.
👉 Athena can now query email, joining_date and manager columns.

📌 Simple Rule:

S3 Data Changed
         ↓
Metadata Not Updated
         ↓
Run Glue Crawler
         ↓
Glue Catalog Updated
         ↓
Athena Reads Latest Schema


🟢 Creating Tables [External Tables] in Athena

🔸 Athena tables are External Tables.
🔸 Metadata stored in Glue Catalog.
🔸 Data remains in S3.

📌 Method 1  
🔸 Manual Table Creation
🔸 CREATE EXTERNAL TABLE employee (...)
  
📌 Method 2:
🔸 Glue Crawler
🔸 Automatically creates tables.

👉 Dropping a table removes metadata only, not S3 data.


🟢 Why Parquet is Popular?

Benefits:
🔸 Columnar storage
🔸 Better compression
🔸 Faster queries
🔸 Reduced storage usage
🔸 Lower Athena cost

Common Compression:
🔸 CSV → .gz
🔸 Parquet → Snappy

🟢 Why do we have different File Formats (CSV, JSON, Parquet) in Athena?

Athena supports multiple file formats because different applications generate data in different formats and each format has its own advantages.

➡ CSV (Comma Separated Values)

Best For:
🔸 Excel reports
🔸 Database exports
🔸 Simple tabular data
E.g:
id,name,salary
101,John,50000
102,David,60000

➡ Why use CSV?
🔸 Easy to create and read.
🔸 Human-readable format.
🔸 Commonly used for data exchange.
👉 Example: MySQL Export → CSV → S3 → Athena


➡ JSON (Semi-Structured Data)

Best for:
🔸 APIs
🔸 Application logs
🔸 Dynamic schema data
E.g:
{
  "id":101,
  "name":"John",
  "salary":50000
}

➡ Why use JSON?
🔸 Flexible schema.
🔸 Can store nested data.
🔸 Widely used by web and mobile applications.

👉 Example: Application/API → JSON → S3 → Athena

➡ Parquet (Columnar Format)
Best for:
Data Lakes
Analytics
Big Data workloads

Employee Data
├── id
├── name
├── salary
├── department
└── location


🟢 Why does Athena support CSV, JSON and Parquet?

🔸 CSV is used for simple tabular data.
🔸 JSON is used for semi-structured and API data.
🔸 Parquet is used for analytics and big-data workloads because it provides better compression and faster query performance.
👉 Preferred format for Athena in production: Parquet. ✅

➡ Imagine an E-Commerce Application:
🔸 Customer orders are generated from an application → JSON
🔸 Daily sales report exported from MySQL → CSV
🔸 Historical sales data converted for analytics → Parquet
👉 All three files can be stored in S3, and Athena can query them.


🟢 Ways to Explore and Understand Files Stored in S3 (CSV, JSON, Parquet) Files ?

➡ If a file is uploaded to S3 and you want to understand its structure, you may need to identify:
🔸 Column Names
🔸 Data Types
🔸 Schema Structure
🔸 Sample Data
🔸 Record Count

➡ S3 Select is used to preview data directly from files stored in S3.
🔸 Example: SELECT * FROM S3Object s;
🔸 View sample records
🔸 Understand the structure of data
🔸 Supports CSV, JSON, and Parquet

➡ AWS Glue Crawler is used for automatic schema discovery.
🔸 Detects column names
🔸 Detects data types
🔸 Creates metadata in Glue Data Catalog
🔸 Updates metadata when new columns are added


➡ Pandas DataFrame is used for local data exploration and analysis.
Example:
import pandas as pd
df = pd.read_parquet('s3://bucket/file.parquet')
df.head()
df.info()
✅ View sample data
✅ View column names
✅ View data types
✅ Understand file structure


➡ PySpark DataFrame -> Used for exploring large datasets.
Example:
df = spark.read.parquet('s3://bucket/file.parquet')
df.show()
df.printSchema()
df.count()
✅ View schema
✅ View column names
✅ View data types
✅ View total record count

Features:

🟢 Recent Queries

Athena maintains query history.

Used to:
🔸 View previously executed queries.
🔸 Re-run queries without rewriting SQL.
🔸 Troubleshoot failed queries.
🔸 Track query activity.
🔸 Review query execution details.

👉 Useful for monitoring and validating query execution during testing and troubleshooting.


🟢 Explain Option in Athena Query Editor

Purpose is to understand how Athena executes a query.

Example:
EXPLAIN
SELECT *
FROM employee
WHERE age > 30;

Query execution plan shows:
🔸 Filter operations.
🔸 Join operations.
🔸 Aggregations.
🔸 Logical plan.
🔸 Query optimization details.

👉 Use Case: Before running complex queries, use EXPLAIN to understand how Athena will process the data.


🟢 Is Scheduling Possible in Athena?

Yes, Athena queries can be scheduled, but Athena itself does not have a built-in scheduler like a database job scheduler.

Scheduling is typically done using:
🔸 Amazon EventBridge (CloudWatch Events)
🔸 AWS Lambda
🔸 AWS Step Functions

👉 Typical Flow:

Athena Query
      ↓
EventBridge Schedule
      ↓
Lambda / Step Functions
      ↓
Execute Athena Query Automatically

Examples:

🔸 What is the datatype?

Examples:

🎯 Historical Data Analysis  ->  Analyze previous months or years of data stored in S3.

🎯 Data Quality Checks ->  Validate incoming files.

Examples:

Examples:

🟢 When Does a Data Engineer Use Athena?

A Data Engineer typically uses Athena when:
🔸 Data is already available in S3.
🔸 Quick SQL analysis is required.
🔸 Data validation needs to be performed.
🔸 CSV, JSON, or Parquet files need to be explored.
🔸 ETL load verification is required.
🔸 Reports need to be generated without creating a database.

📌 Simple Rule
👉 Data stored in S3 + SQL Query Requirement = Athena
👉 Historical Reporting + Dedicated Data Warehouse = Redshift
👉 Dashboards and Charts = QuickSight / Power BI / Tableau


🎯 Key Takeaway
✔ Athena is a serverless query engine used to analyze data stored in Amazon S3 using SQL.
✔ Glue Data Catalog acts as the central metadata repository for databases, tables, columns, partitions, and data types.
✔ Glue Crawler automatically discovers schemas and keeps metadata synchronized with changes in S3 data.
✔ QuickSight is used for creating dashboards, charts, and visual reports using Athena as a data source.
✔ Parquet is the preferred file format for Athena workloads due to better compression, faster query performance, and lower query costs.
✔ Data remains in S3; Athena only reads the data using metadata stored in the Glue Data Catalog.
